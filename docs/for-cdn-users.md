# Browser ESM without a bundler

VisDelta can run directly from one versioned ESM URL. Like D3, the package root
is the canonical import: jsDelivr reads VisDelta's `module` entry, rewrites its
bare `d3-*` dependencies to version-pinned CDN modules, and preserves lazy chart
plugin imports. This template creates a transition controlled by a slider.

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/visdelta@0.3.0/dist/visdelta.css">
  </head>
  <body>
    <div id="chart"></div>
    <input id="progress" type="range" min="0" max="1" step="0.01" value="0">

    <script type="module">
      import * as vd from "https://cdn.jsdelivr.net/npm/visdelta@0.3.0/+esm";

      const rows = [
        { category: "A", revenue: 12, profit: 5 },
        { category: "B", revenue: 18, profit: 11 },
        { category: "C", revenue: 9, profit: 7 }
      ];

      const from = vd.bar(rows).x("category").y("revenue").key("category");
      const to = from.y("profit");
      const change = await vd.transition(from, to, { target: "#chart" });

      progress.addEventListener("input", event => {
        change.progress(event.currentTarget.valueAsNumber);
      });
    </script>
  </body>
</html>
```

The `/+esm` suffix matters: VisDelta's published ESM entry imports the `d3-*`
modules by bare name, which a browser cannot resolve on its own. jsDelivr's
generated module rewrites those imports to CDN URLs such as
`/npm/d3-scale@4.0.2/+esm`. Pin the VisDelta version for durable pages. Do not
use SRI with `+esm`: it is generated by jsDelivr rather than stored as a static
file.

The namespace name `vd` is local to your module; it is not a browser global.
It keeps the root-package example explicit (`vd.bar`, `vd.transition`) and
matches the familiar `import * as d3` form. Named imports remain useful for the
focused entries below.

## Focused entries

The root URL is recommended for ordinary pages. It exposes the complete public
authoring API, while chart renderers still load lazily. When a page deliberately
wants a narrower initial authoring entry, it can request a packaged file:

```js
import { bar } from "https://cdn.jsdelivr.net/npm/visdelta@0.3.0/dist/bar.js/+esm";
import { transition } from "https://cdn.jsdelivr.net/npm/visdelta@0.3.0/dist/transition-entry.js/+esm";
```

These longer URLs are an optimization, not the default learning path.

A complete slider-driven page using the recommended root ESM import is in
[`examples/cdn-demo.html`](https://github.com/SonghaiFan/visdelta/blob/main/examples/cdn-demo.html).

## Global script

For a page without modules, load the self-contained global bundle. The `d3-*`
modules VisDelta uses are compiled in; nothing else is needed.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/visdelta@0.3.0/dist/visdelta.css">
<script src="https://cdn.jsdelivr.net/npm/visdelta@0.3.0"></script>
<script>
  const { bar, transition } = VisDelta;
  // same authoring code as above
</script>
```

VisDelta executes declared transforms itself. Use `.where()`, `.sort()`,
`.breakdown()`, and `.rollup()` directly; authors do not import or pass another
runtime.

The browser-global build exposes the same chart and transition API as
`window.VisDelta`.
