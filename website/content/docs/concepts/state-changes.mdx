---
title: State changes
description: delta() names every difference between two states with seven categories and a small set of directional actions.
---

`delta(from, to)` compares two states of the same chart type and returns
`stateChanges`: a list of directional facts drawn from a closed vocabulary.

```ts
import { delta } from 'visdelta/core';

const change = delta(revenue, profit);
change.stateChanges;
// [{ category: 'encoding', action: 'remap', channel: 'y' }]
```

`delta()` is DOM-free and runs anywhere, including Node. Every transition
controller exposes the same result as `change.delta`.

## Category boundaries

- **Data** is source-record membership or value change. An `update` is reported
  only when stable datum identity provides evidence for it.
- **Grain** covers grouping and measure semantics. Changing `sum` to `mean` is
  `change-reducer` even when grouping is unchanged. A Unit chart's `unitValue`
  also belongs here, because it changes what one mark represents.
- **Encoding** is a data-field binding. A field-driven `.color('region')` is
  Encoding; a constant `.color('#3366ff')` is Appearance.
- **Coordinate** is the positional scale, domain or orientation. Remapping y to
  another field is Encoding; `.flip()` and a log scale are Coordinate.
- **Layout** is the arrangement, order or connection of the same objects.
- **Attention** preserves data and marks while focus moves the camera or
  highlight changes emphasis. It carries a `target` of `focus` or `highlight`.
- **Appearance** is fixed visual styling or form that binds no field.

## Several categories at once

Categories are non-exclusive. One pair of states can produce several facts:

```ts
const detailed = bar(sales)
  .x('region').y('revenue')
  .key(['region', 'channel'])
  .breakdown('channel')
  .color('channel');

delta(detailed.rollup(), detailed).stateChanges;
// grain.split, encoding.bind (color), appearance.restyle
```

Timing set with `.transition({ duration })` describes how a state animates, not
what it shows, so on its own it reports no state change.

## Not a playback schedule

The array's order is categorical and stable, for inspection only. It is **not**
a priority list, a route or an animation script. How a transition actually moves
is chosen by the chart module, see [Transitions](/docs/concepts/transitions).

## Lower-level results

`stateChanges` is the normalized view. The same result also includes:

| Field                    | Meaning                                                                |
| ------------------------ | ---------------------------------------------------------------------- |
| `deltas`, `hasDelta(type)` | Raw semantic differences, e.g. `change.hasDelta('encoding.y')`       |
| `edits`                  | Exact, lossless edits to the serialized declaration                    |
| `lineage`                | Mark correspondence through source records, when both states have inline data |

See [Identity and lineage](/docs/concepts/identity) and the
[core API](/docs/api/core) for these.
